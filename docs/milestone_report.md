**Team Members:** Julian Mohamed (86818358), Leo Cabral (30036610), Michael Montgomery (43400977), Vinay Dhillon (34519512).

**Progress to Date**
We have completed the data cleaning, network construction and first round of analysis described in weeks one to five of our proposal timeline. Using the TransLink GTFS feed, we built a directed network for a typical weekday (Wednesday, November 18, 2026) covering 25,705 scheduled trips on 236 routes. The network has 8,657 nodes (stops and stations) and 15,391 edges. Of these, 9,992 are direct rides between consecutive stops, weighted by scheduled travel time, and 5,399 are walking transfers. The average total degree is 3.56, the density is 0.0002, and the average shortest path is 30 stops or about 67 minutes. A low average degree like this is normal for a transit network, since most stops only link to the stop before and after them. Our early results show that SkyTrain stations dominate betweenness, with Lougheed Town Centre, Columbia and Commercial-Broadway at the top. Removing the 10 highest-betweenness stations lowers network efficiency to 88% of normal, compared to 99% when 10 random stations are removed. Removing all walking transfers between modes lowers efficiency to 58%, which suggests that bus and rail depend on each other heavily.

**Challenges Faced**
The first challenge was the size and format of the data. The feed has over 1.8 million stop time records covering every service day, so combining them all would mix weekday, weekend and holiday schedules into the same edge weights. We solved this by keeping only the trips that run on one representative weekday, using the calendar and calendar exception files. The raw times also needed cleaning: they have leading spaces, they go past 24:00 for late-night trips, and they are rounded to 30 seconds, so some short hops show a travel time of zero. We also removed HandyDART, since it is an on-demand service and not a fixed route.

The second challenge was deciding what a node should be. In GTFS, each side of a street is a separate stop and each SkyTrain platform is a separate stop. Under this definition almost every node has a degree of two to four, so degree on its own says very little about importance. We merged SkyTrain platforms into their parent stations. We also had to match West Coast Express platforms to their stations by name, because the feed does not link them. For bus stops, we used the number of routes serving a stop as our measure of how connected it looks, since that fits our third research question better than raw degree.

The third challenge was connecting the different modes. Buses and trains never share a stop ID, so without extra edges the bus and rail networks would be completely separate. The transfer file that comes with the feed is incomplete. For example, it does not link Templeton Station to the bus stop right outside it. We added walking edges between every rapid transit station and any stop within 400 metres. Our results are sensitive to this assumption, so we will need to test it.

The fourth challenge was choosing metrics that work on a directed network that is not fully connected. Bowen Island's bus stops form their own component, because the island is only reached by BC Ferries, and there are 27 strongly connected components in total. Standard closeness centrality gives misleading values in this case, so we switched to harmonic closeness. For the same reason, we measure resilience with network efficiency and the size of the largest component instead of average path length, because average path length can actually go down when parts of the network break off. We estimate efficiency from a fixed sample of 300 source stops so that each removal simulation runs in seconds.

**What Is Left To Do**
For the bottleneck questions, we plan to group the bus bays at major exchanges together with their SkyTrain station, so that a station like Surrey Central is treated as one hub rather than many small stops. For resilience, we want to add adaptive removal, where centrality is recalculated after each station is removed. We also want to simulate shutting down whole lines, such as the Canada Line or the SeaBus, and to map which neighbourhoods become cut off when a hub closes. We need to test how sensitive our results are to the 400 metre walking radius and the chosen service day, and to add waiting time based on route frequency to the edge weights, since they currently only count time spent on the vehicle. We also still need to decide how to include BC Transit data, most likely as a smaller comparison network such as Victoria or Kelowna.
